Connect to your tenant

Sign in with the account you manage SharePoint with. The tool reads sites, libraries and usage through Microsoft Graph and SharePoint REST, as you.

Delegated permissions, asked when they are first needed:

  • At sign-in, Graph User.Read and Sites.Read.All: who you are, site analytics, page edits, drive activity and storage.
  • At the first discovery, SharePoint AllSites.Read: search, site and library dates, owners.
  • Only for OneDrive discovery and force scan, SharePoint admin AllSites.FullControl. That also needs the SharePoint Administrator role.

Site discovery

SharePoint sites come from search, OneDrives from the tenant admin API. Nothing changes in the tenant unless you use force scan and confirm it.

Without force scan the tool only sees sites you can already open; the rest end up as No access. With force scan it first checks every selected site. Where you are not admin it adds you, after you confirm the list, and removes you again when the analysis is done. Sites where you are admin already, or where the check fails, are left alone. The list of added rights is kept in this browser until they are removed, so an interrupted run can be cleaned up later. Needs the SharePoint Administrator role.

About SPOTrim

SPOTrim finds stale SharePoint and OneDrive sites. For every site it collects several "last changed" and "last viewed" signals, gives a recommendation and shows how it got there.

Discovery

  • SharePoint sites: SharePoint Search, contentclass:STS_Site. Search only returns sites you can open.
  • OneDrive sites: tenant admin API SPO.Tenant/GetSitePropertiesFromSharePointByFilters, which returns all of them. Needs the SharePoint Administrator role.
  • The site type (communication, team, group, Teams channel, OneDrive, hub, app catalog and so on) comes from the web template.

Last modified

The most recent of:

  • lastModifiedDateTime of the site, from discovery.
  • LastItemUserModifiedDate from _api/web. Excludes system and crawl updates.
  • The latest LastItemUserModifiedDate of the visible document libraries, from _api/web/lists.
  • The most recently edited modern page or news post, Graph /sites/{id}/pages.

Last viewed and usage

One Graph $batch per site:

  • analytics/allTime: all access ever recorded, plus distinct actors.
  • analytics/lastSevenDays: access in the last 7 days.
  • drive/items/root/getActivitiesByInterval: daily activity on the default library for 30 days. Gives the last active day.
  • drive?$select=quota: storage used.

Recommendations

  • Keep: modified within the stale threshold, or a system site (root, search, app catalog, content type hub and the like).
  • Review: not modified within the threshold but still opened in the last 30 or 7 days, or with all-time views. Usually an archive or reference site.
  • Clean up: not modified within the threshold and no views at all, or not viewed within the threshold either.
  • No access: _api/web and _api/web/lists both answered 401 or 403.
  • Unknown: no modification date for another reason, for example a server error.

Force scan

  • Checks _api/web/currentuser on each selected site. Only a clear "not admin" (or a 403) counts. Throttling, server errors and token errors mean unknown: that site is not touched and is listed after the run.
  • Shows the exact list of sites before anything changes. OneDrives are left out unless you tick them.
  • Adds you with SetSiteAdmin through the tenant admin endpoint and removes you again after the analysis, also when you cancel. Only sites where the tool added you are removed.
  • Each added site is written to this browser's local storage (site URL, account, tenant id, time) before the change is sent. If the run is interrupted, the next visit offers to remove them.
