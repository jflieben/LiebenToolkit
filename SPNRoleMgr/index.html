            About SPNRoleMgr

            SPNRoleMgr shows and changes the API permissions of any service principal or managed identity in your tenant. It works like "Add a permission" on an app registration, but also for service principals without an app registration in your tenant: managed identities, gallery apps and multi-tenant apps.

            What it does

            • Lists every service principal in the tenant, with filters on type and Microsoft first-party. Exports to Excel or CSV.
            • For the picked service principal: its application permissions (appRoleAssignments) and delegated grants (oauth2PermissionGrants).
            • Revokes the permissions and delegated scopes you tick, or everything at once when you want a clean slate.
            • Grants application or delegated permissions on any API in the tenant: Microsoft Graph, SharePoint, Exchange, Azure Storage, third-party APIs. APIs are picked by appId, so two APIs with the same name cannot be mixed up.
            • For service principals with Sites.Selected (Microsoft Graph or SharePoint Online): grants, changes or removes their access per SharePoint site. Sites it already reaches are listed first. Grants of other apps on a site can be removed as well.
            • When you are not an admin of a site, it can make you site collection admin for the change, and asks after each change whether to remove that again.
            • Every change dialog shows the tenant, the service principal and each permission that is added or removed.

            How it works

            • Listing: GET /servicePrincipals?$top=999 with ConsistencyLevel: eventual.
            • Permissions: GET /servicePrincipals/{id}/appRoleAssignments and /oauth2PermissionGrants in parallel. Role and scope ids are translated to names through the resource service principal.
            • Application permissions: POST /servicePrincipals/{id}/appRoleAssignments with principalId, resourceId and appRoleId; revoke is a DELETE on the assignment.
            • Delegated permissions: scopes are added to the existing AllPrincipals grant for that API (PATCH), or a new one is created. Removing the last scope deletes the grant.
            • Site access: /sites/{id}/permissions. Sites.Selected works per site collection, so a subsite or library URL resolves to its collection. Only https://*.sharepoint.com URLs are accepted.
            • Site list: every site collection from the SharePoint admin API (GetSitePropertiesFromSharePointByFilters), filtered in the browser on any part of the name or URL. Without SharePoint admin access it falls back to Graph search, which matches whole words and prefixes only. Listed sites are checked one by one for a grant to this service principal.
            • Temporary site admin: Tenant.SetSiteAdmin on the SharePoint admin API, only after you confirm. The site is written to this browser's local storage before the call, so a closed tab does not hide it: the next visit lists it with a button to remove it.
            • Tenant check: every token is checked against the tenant you signed in to. If a consent popup ends up in another account, the call is refused before anything changes.

            Questions this tool does not answer

            SPNRoleMgr changes one service principal at a time and reads only what Entra and Graph store. These questions need a scan of the whole tenant, which M365Permissions does:

            • Which service principals hold which permissions, across the tenant and over time: Entra ID permissions review.
            • Which apps can read every mailbox, including grants made with Exchange RBAC for Applications: which apps can read every mailbox.
            • Which apps have Sites.Selected access on which sites, next to users, groups and sharing links: SharePoint permissions report for all sites.
            • Everyone and everything with access to one site: who has access to a SharePoint site.

            What it does not do

            • Change the API an app publishes (its own appRoles or oauth2PermissionScopes). Edit the app registration for that.
            • Assign Entra directory roles, configure Conditional Access, or manage secrets and certificates.

            Permissions

            Browsing needs Application.Read.All and Directory.Read.All. Your first confirmed change asks for AppRoleAssignment.ReadWrite.All and DelegatedPermissionGrant.ReadWrite.All. Tenant-wide grants also need Privileged Role Administrator, Cloud Application Administrator, Application Administrator or Global Administrator.

            The SharePoint site manager is opt-in: opening it the first time asks for Sites.FullControl.All (delegated, admin consent), the only scope Graph accepts for site permissions. You also need SharePoint Administrator or higher. The full site list and temporary site admin use the SharePoint admin API, which asks for SharePoint access for this app the first time.
