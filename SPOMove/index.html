What kind of transfer is this?

    Inside one Microsoft 365 tenant, or from one tenant to another.

    Connect the source tenant

    Sign in to the tenant that holds the files. The sign-in opens in a popup so the wizard keeps its state.

    Delegated permissions:

    • User.Read who you are and which tenant
    • SharePoint .default (the app's SharePoint permission, AllSites.FullControl) to read, write and delete files, set metadata, list all sites and take ownership
    • User.ReadBasic.All only when you use the OneDrive (by user) picker

    Pick the source location

    Search for a site or paste its URL, pick a document library and optionally a subfolder. Everything under that folder is transferred.

    Connect the target tenant

    Sign in to the destination tenant in a second popup. Both connections stay active side by side.

    Pick the target location

    Where the files should land. Missing folders are created.

    Transfer options

    Off: target files get you as author and editor and now as the dates. Author and Editor only carry over when the same user exists in the target.

    Replays every older version in order. All versions stream through your browser, so this is a lot slower.

    Off: a file that already exists on the target is skipped and left alone, also when versions are included.

    Compares the last modified time (UTC). Target files of the same age or newer are skipped.

    Review and start

    SPOMove first scans the source folder for the file list, then starts transferring. Follow it, pause, resume or cancel on the Jobs tab.

    Transfer jobs

    Jobs live in this browser. If a run stops (tab closed, network gone) resume it here; files already done are skipped.

    No jobs yet

    Start one on the New transfer tab.

    Take ownership grants that are not linked to a job (any more). They stay until you remove them.

    About SPOMove

    SPOMove moves or copies SharePoint Online files between sites, in one tenant or between two tenants. It signs you in with Microsoft and calls Microsoft Graph and the SharePoint REST API as you. File contents go from Microsoft to your browser and back to Microsoft, nowhere else.

    How transfers run

    • Same tenant: SharePoint's server-side SP.MoveCopyUtil, so the bytes never pass through your browser. Fast, also for big libraries.
    • Between tenants: download from the source, upload to the target (chunked above 10 MB). Bound by your connection and memory.
    • Previous versions: every older version is replayed in order onto the target, best effort, through the browser.
    • Metadata: Author, Editor, Created and Modified are kept where the users resolve in the target web.
    • Overwrite off: a file that already exists on the target is skipped, versions included.
    • Deletes: everything SPOMove removes (move sources, replaced targets, sync deletes) goes to the site recycle bin.
    • Source and target may not be the same folder or inside each other.

    Finding source and target

    • Sites: search sites you can reach, or paste a site URL of the connected tenant.
    • OneDrive (by user): type a name or UPN to open that user's OneDrive.
    • All sites (admin): with the SharePoint Administrator role, every site collection in the tenant, also the ones you cannot open yet.

    Jobs, resume and sync

    Jobs and their per-file progress are kept in this browser (local storage and IndexedDB, no tokens). After an interruption, Resume only does what is left. Several jobs can run at once. A finished job can be re-run: Sync changes transfers new and changed files. For copy jobs it also lists files that are gone from the source and deletes those on the target only after you confirm the list. When a source folder cannot be listed, the run shows which ones and deletes nothing. Clear all job data removes the history.

    Reports

    When a job finishes its report opens: result chart, totals, duration, average speed and every file with its status and error, filterable and exportable to Excel or CSV.

    Taking ownership

    When you cannot open a site and you hold the SharePoint Administrator role, SPOMove can add you as site collection admin after you confirm it. The grant is recorded on the job (or in the Jobs tab when no job uses it) and stays until you click Remove my site admin rights, which removes exactly the grants SPOMove made. The job card and the report remind you while any are left.

    Sign-in

    Two connections, source and target, each in its own popup. Tokens stay in this tab. Resuming a job after a reload only reuses the exact account the job ran as; otherwise you sign in again with that account filled in, and a sign-in to another tenant is refused.
